## Origin

The Astro content-collection loader + the expandable reference UI on tool pages are an EXPLICIT FOLLOW-UP change, NOT in scope here. Producers in the 7 tool repos are already seeded as fab/backlog.md items and are out of scope.

This change emerged from a `/fab-discuss` session. The user observed that the 7 tools documented on shll.ai (`idea`, `hop`, `fab-kit`/`fab`, `wt`, `run-kit`/`rk`, `tu`, `shll`) have no place for detailed command documentation on the site — the canonical detail lives only in each tool's `-h` / `--help` output and subcommand help (e.g. `wt -h`, `rk riff -h`). The goal: make the site reflect those help/man pages without introducing documentation drift.

**Interaction mode**: conversational, multi-turn. A series of decisions was made before this intake (see Assumptions). The investigation confirmed concrete facts against the real repos rather than assuming them.

**Key decisions reached during discussion** (all recorded in Assumptions with discussion provenance):
1. Help content is *generated by the binary*, not hand-written — so capturing it at build time eliminates drift, resolving the tension with the existing tool-page-rubric (which forbids hand-copied long-form reference).
2. The cross-repo contract is a per-tool `help/<tool>.json` file collected at the **shll.ai repo root** (not inside any `sites/<name>/`), so it survives a live-site swap and is shared across site variants (Constitution II — Multi-Site Isolation).
3. The producing repos push *into* shll.ai (chosen over site-pulls-at-build), specifically via **PR + auto-merge** using the already-created `SHLLAI_TOKEN` repo secret, to avoid a multi-repo push race on `main` and keep every site change reviewable.
4. The node shape carries raw `-h` `text` (byte-for-byte fidelity, terminal-authentic) **plus** structured `short`/`usage`/`path` fields that come free from Cobra — so the site can render a collapsible tree without re-parsing the blob.
5. Producers are **per-repo, framework-native** (no shared Go library): 6 are Cobra/Go (walk the command tree via `rootCmd.Commands()` recursively), `tu` is Node/TS and flag-based (flat, bespoke producer). Shared-library was rejected as higher maintenance than copy-paste for ~40 frozen lines.
6. Scope was sequenced **"backlogs first, site later"**: the 7 producer backlog items were already seeded (done before this intake); this change does the shll.ai *consume-side contract*; the Astro loader + UI is an explicit follow-up change.

## Why

**Problem.** shll.ai is a directory into the toolkit, but a visitor who wants to know "what flags does `wt create` take?" or "what subcommands does `rk` have?" has to leave the site and read a GitHub README — and the READMEs themselves often don't reproduce full `-h` output. The authoritative command reference (the binary's own help) is nowhere on the site.

**Why not just hand-write it?** The existing `tool-page-rubric` explicitly forbids long-form command reference on tool pages, and for good reason: hand-copied docs drift from the binary. The constitution's External Links section reinforces that stale/inaccurate pointers erode the site's value. So the naive fix (paste `-h` output into markdown) is both rubric-violating and drift-prone.

**Why this approach.** Help text is *machine-generated by the binary*. If each tool emits its own help as structured JSON at build time and the site renders that, the reference is as fresh as the last build *by construction* — there is no hand-maintained copy to drift. This turns a forbidden pattern (long-form reference) into a safe one (generated, single-sourced from the binary that defines it).

**Consequence of not doing it.** The site stays a shallow directory; the richest, most authoritative content each tool already produces (its help tree) remains invisible to site visitors, and any attempt to add it by hand would rot.

**Why scope only the contract here.** The producers live in 7 *other* repos, each with its own fab pipeline; implementing them from here would bypass those pipelines. By freezing the `help/<tool>.json` schema + reference sample + push model *first*, all 7 repos (already seeded with backlog items) can build their producers in parallel against a stable contract. The site's rendering layer can then be built against real committed data.

## What Changes

This change delivers the **consume-side contract** in the shll.ai repo. It does NOT build the rendering UI (explicit follow-up) and does NOT touch the 7 tool repos (already seeded).

### 1. The `help/<tool>.json` schema (the cross-repo contract)

A single JSON file per tool, validated against a documented schema. The shape (frozen during discussion, validated against the real `wt` binary):

```jsonc
{
  "tool": "wt",                    // the invoked binary name (e.g. "rk", "fab")
  "version": "1.4.2",              // from the built binary (ldflags / rootCmd.Version) — NOT hardcoded
  "captured_at": "2026-06-02T00:00:00Z",  // ISO-8601 UTC, stamped at capture
  "schema_version": 1,             // lets the contract evolve without a flag-day across 8 repos
  "root": {                        // recursive Node
    "name": "wt",                  // command name at this level
    "path": "wt",                  // full invocation path (e.g. "rk riff") — drives the tree label
    "short": "Git worktree management — ...",  // one-line description
    "usage": "wt [command]",       // usage line
    "text": "<raw -h output, byte-for-byte, newlines preserved>",
    "commands": [ /* Node[], recursive; empty array = leaf */ ]
  }
}
```

`Node = { name, path, short, usage, text, commands: Node[] }`, recursive. Every node carries both raw `text` *and* structured `short`/`usage` — mild redundancy accepted because the structured fields come free from Cobra and let the site render a tree without parsing `text`.

**Producer rules that the schema doc must state** (these constrain the 7 producers, already in their backlog items):
- Filter out Cobra's auto-generated `completion` and `help` subcommands and any `cmd.Hidden == true` node.
- Walk the framework's command tree programmatically (Cobra: `rootCmd.Commands()` recursively); do NOT regex-parse `-h` text to discover structure.
- `version` is read from the built binary, never hardcoded.
- `tu` is the exception: Node/TS, flag-based, no subcommands → flat tree (`commands: []`), bespoke producer capturing `tu --help`.

### 2. The `help/` collector directory

A top-level `help/` directory at the **shll.ai repo root** (sibling to `sites/`, `fab/`, `docs/`), holding `help/<tool>.json` per tool. Placement rationale: it is project-level data shared across site variants, not owned by `astro-tailwind-terminal1` — keeps it honest with Constitution II and survives a live-site swap. The directory is the inbox that the 7 tool repos write to via PR.

File naming uses the tool's **repo/site slug** (`help/run-kit.json`, `help/fab-kit.json`) even where the binary differs (`rk`, `fab`); the `tool` field inside carries the invoked binary name.

### 3. The reference sample `help/wt.json`

Already generated (during discussion) from the *real* `wt` Cobra binary — every `text` field is byte-for-byte `-h` output. This change commits it as the canonical example the other 6 tools copy from. It exercises every case: rich top-level text with a preamble, multi-flag subcommands, a near-empty leaf (`init`), a node with two `Usage:` blocks (`shell-init`), and `commands: []` leaves. Caveat to document: its `version` is a placeholder (`1.4.2`) because a plain `go build` reports `dev`; real producers inject the true version.

### 4. Cross-repo push model documentation

Document the agreed mechanism so the 7 backlog items build against it:
- Each tool's CI, after build, runs its producer, writes `help/<tool>.json`, validates it parses, then **opens a PR into `sahil87/shll.ai` with auto-merge enabled** (NOT a direct push to `main`).
- Auth: the **existing `SHLLAI_TOKEN`** repo secret (already created in all 7 repos) with `contents` + `pull-request` write scope on shll.ai.
- Rationale: a direct push from 7 repos races on `main` (non-fast-forward rejections / clobbers when two tools' CI finish near-simultaneously). PR + auto-merge serializes merges and yields a reviewable `help.json` diff for free; cost is one small workflow in shll.ai.

### 4b. Receiving-side workflow in shll.ai (IN SCOPE — resolved Q12)

A minimal GitHub Actions workflow in shll.ai that completes the inbound loop for the 7 producers:
- Triggers on the inbound `help/<tool>.json` PRs (e.g. PRs touching `help/**`, opened by the bot/token identity).
- Enables auto-merge so producer PRs serialize and merge without manual intervention (the existing deploy-on-push-to-`main` workflow then ships the site).
- Spec to decide the exact trigger surface (path filter `help/**`, optional label/actor gate) and whether a separate deploy trigger is needed beyond the existing push-to-`main` deploy. Note: under Constitution IV (deploy via CI on push to `main`), merging the PR already triggers the existing deploy — so "deploy on merge" likely needs no new workflow, only the auto-merge enablement.

### 4c. Formal Zod schema for `help/<tool>.json` (IN SCOPE — resolved Q13)

A machine-checkable Zod schema defining the recursive `Node` and the envelope, committed in this change as the authoritative contract:
- One source of truth that BOTH the 7 producers validate their output against AND the follow-up Astro loader reuses (no second, drifting definition).
- Placement (spec to finalize): a standalone `.ts`/`.mjs` schema module the loader can import later, kept where the follow-up loader will live or in a shared location — must not pull the Astro runtime into a contract-only change.
- Recursive `Node` requires a lazy/recursive zod definition (`z.lazy`) for `commands: Node[]`.

### 5. Amend the tool-page-rubric

Update `docs/memory/conventions/tool-page-rubric.md` to permit an expandable "Command reference" section at the bottom of each tool page (below "Full docs"), sourced from `help/<tool>.json`. The amendment must preserve the rubric's anti-drift intent by stating that this section is *generated, not hand-written* — the one exception to "SHALL NOT contain long-form command reference," justified precisely because it is single-sourced from the binary. Record the placement decision (expandable section on the existing page, chosen over a separate `/tools/{tool}/help` route or a top-level `/reference` section).

### Out of scope (explicit)

- The Astro content-collection loader for `help/` and the expandable reference UI on tool pages — **follow-up change**.
- The 7 producers in the tool repos — already seeded as `fab/backlog.md` items (`idea`:nnsn, `hop`:jr5f, `wt`:pc47, `run-kit`:a36m, `shll`:ep4z, `fab-kit`:xob7, `tu`:v76l).
