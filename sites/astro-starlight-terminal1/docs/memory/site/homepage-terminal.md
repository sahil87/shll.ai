# Homepage Interactive Terminal

## Overview

The homepage hero (`src/content/docs/index.mdx`) is a terminal transcript that **looks** interactive. Change `9vbo` makes the final prompt line **actually typeable** — keystrokes echo, Enter runs a command against a static in-page map, output prints in the same styled stream — layered as a **progressive enhancement** so nothing regresses without JS. The terminal SKIN (JetBrains Mono, phosphor-amber `--c-*` palette, `.shell-*` classes) shipped earlier in `260517-pdsp-terminal-skin`; this change adds behavior on top of that skin (reusing its classes verbatim) plus **one** deliberate visual addition — a `.terminal-window` frame around the transcript. Change `n23o` layers real shell affordances onto input handling (§ Shell affordances); change `23xc` makes the interactivity **discoverable above the fold** (§ Above-the-fold activation pass); change `by18` makes it **usable on touch devices** (§ Touch support); change `cuur` polishes the **command experience** (did-you-mean, `help <command>`, a cancellable navigation beat) and makes its **output accessible** (live-region announcements, reduced-motion gate) (§ Command polish & accessible output); change `o33t` lands the **delight pass** the backlog sequenced last — 33 new unlisted GNU-utils easter eggs (stateless one-shots, light logic, three animated streams) on new streamer + live-region-noise infrastructure (§ GNU-utils delight pass); change `cdbr` adds the **sanctioned full-roster reveal** — the `cheatsheet` command mapping all 52 keys in five groups behind a runtime anti-drift coverage check, pointed to by the one sanctioned help-footer change (§ The full-roster cheatsheet); change `37ng` fixes the **funnel's hottest dead end** — a bare tool name now prints that tool's card, mechanically sourced from `help/<slug>.json` at build time (§ Tool-name cards).

All work is scoped to this site only (`sites/astro-starlight-terminal1/`, the LIVE build per `SITE_DIR`). Zero new dependencies; output stays fully static (Constitution I, VI).

## The progressive-enhancement boundary (load-bearing)

The static `<pre class="shell-session">` transcript in `index.mdx` is the **no-JS source of truth** — crawlers, no-JS, and pre-hydration paint see the full hand-written transcript verbatim, including the version-block `<a>` links and the final blinking `$ ▊` line. Nothing regresses without JS.

`src/components/TerminalPrompt.astro` is a **client island** following the `Diagram.astro` precedent (frontmatter comment + a single `<script>` module island). With JS on, it:

1. Locates the final prompt line via the **`data-terminal-prompt`** attribute (a marker on the last `.shell-line` in `index.mdx`), not positional assumptions — keeping the static markup authoritative.
2. **Removes** that static `$ ▊` line, prints the greeting line (change `23xc`, § Above-the-fold activation pass), and emits the first live prompt in its place: a `.shell-line` containing a `.shell-prompt` `$` and a focusable `<span class="shell-input" contenteditable="true">` input region — `contenteditable="true"` plus an explicit plain-text paste handler, NOT `plaintext-only` (inconsistently supported; see § Accessibility).
3. On **Enter** (since `by18` via the shared `commitLine(true)` helper — § Touch support): trims the line, freezes the just-entered input into static echoed text (strips `contenteditable`/`role`/aria/listener/`.shell-input`), dispatches the command, appends output spans to the **same** `<pre>` stream, and emits a fresh prompt.

**No autofocus on page load (deliberate).** `freshPrompt(focus = true)` defaults to focusing, but the initial activation calls `freshPrompt(false)` — auto-focusing on load would steal focus and scroll the hero out of view (disruptive for keyboard/SR users). Focus moves to the prompt only **after** the user runs a command (Enter / `clear`). This was a Should-fix finding addressed in the review stage.

### `theme` syncs with Starlight (does not reinvent persistence)

`setTheme` locates the header `starlight-theme-select select`, sets `select.value` to the target, and dispatches a bubbling `change` event — so the header toggle UI, `<html data-theme>`, and `localStorage` all update through Starlight's own `onThemeChange`. It MUST NOT flip `data-theme` directly nor reinvent persistence. No-arg toggles the effective theme (read from `document.documentElement.dataset.theme`); `dark`/`light` sets it; any other arg prints `usage: theme [dark|light]`. A direct `data-theme` flip exists only as a fallback if the header select is absent.

## Shell affordances on `onKeydown` (change `n23o`)

Change `n23o` makes the prompt behave like a real shell rather than a form field. All three features live in input handling (`onKeydown` + module-scoped state inside `initTerminal`) and reuse existing plumbing (`COMMANDS`, `TOOLS`, `freshPrompt`, `clear`, `caretToEnd`, `print`); zero new dependencies (Constitution VI), no markup/content change. The `onKeydown` branch order is: Ctrl-combos → ↑/↓ → Tab → Enter → native fall-through. (Since `by18` the Enter branch is just `e.preventDefault(); commitLine(true);` — the commit sequence itself lives in the shared `commitLine` helper, § Touch support.)

**The exactly-one-trailing-prompt invariant (load-bearing).** The most fragile part of this change. Ctrl-L and Ctrl-C are prompt-emitting paths **outside** the commit flow (`commitLine` — Enter and, since `by18`, command-bar chips), so each must emit exactly one trailing prompt itself — never two, never zero. The Tab multiple-match listing deliberately does NOT commit/freeze the line (so it adds no prompt-emitting path at all).

### Command history (↑ / ↓ recall)

- **State at `initTerminal` scope** (one history per terminal instance, NOT inside `freshPrompt` which runs per prompt): `history: string[]` of committed, non-empty, trimmed **raw** lines + a `historyCursor` ranging `[0, history.length]`, where `length` is the "blank draft" slot past the newest entry. ↑ (`navigateHistory(-1)`) walks toward 0; ↓ (`navigateHistory(1)`) walks toward `length`, where it restores a **blank** line (drafting a new command), not the newest entry. Caret to end via `caretToEnd()`. Because the prompt is enforced single-line (paste flattened, `aria-multiline=false`), ↑/↓ drive history unconditionally rather than caret movement.
- **`ignoredups`** (bash behavior): on Enter commit a line is pushed only if it differs from the immediately previous entry; the cursor then resets to `history.length`. Ctrl-C also resets the cursor to the blank-draft slot (so the next ↑ starts from the newest entry).
- **sessionStorage persistence** under the named key `shll:terminal:history` (deliberately NOT `localStorage` — a refresh keeps recent commands, but a new browser session starts clean). Read once at init via `loadHistory()`, written on each commit via `saveHistory()`. **All** access is try/catch-guarded: private-mode / disabled-storage / quota degrades silently to in-memory-only and never throws, and a malformed / non-array payload coerces to `[]` (the parsed array is also filtered to strings).

### Tab-completion (bash-like)

`completeInput()` completes the token under edit. First token → `COMMANDS` keys; second token → `TOOLS` when the first token is a tool-arg command (`cd` / `open` / `man`, the `TOOL_ARG_COMMANDS` list). Resolution over the candidates matching the typed fragment:

- **single match** → fill it (`fillToken` rejoins the line, preserving any `cd `/`open `/`man ` prefix), caret to end.
- **longest common prefix > typed** → fill the shared prefix (partial completion), no listing.
- **multiple matches, no LCP gain** → `printBeforePrompt({ text: matches.join('  '), classes: 'shell-out' })` lists the candidates ABOVE the still-live input — WITHOUT freezing the line or emitting a new prompt (input text + caret untouched). It uses `printBeforePrompt` (insert before the live prompt line), NOT `print` (append to end of `session`): `print` would drop the listing BELOW the live prompt — the prompt would no longer be the trailing line. This is the chosen path (over freeze→reseed) precisely because it adds no prompt-emitting path, keeping the one-trailing-prompt invariant trivially intact.
- **no match** → no-op (input unchanged, nothing printed).

### Control keys (Ctrl-L, Ctrl-C)

Detected only on an unmodified Ctrl combo (`e.ctrlKey && !shift && !alt && !meta`) so e.g. Ctrl-Shift-C copy is left to the browser; other Ctrl combos fall through to native handling.

- **Ctrl-L** → `preventDefault()` (Ctrl-L otherwise focuses the address bar), reuse `clear()` (which deliberately does NOT emit a prompt itself), then exactly one `freshPrompt()`.
- **Ctrl-C** → `preventDefault()`, `freezeInput('^C')` (freeze the live line with a trailing `^C` like a real shell aborting a line), discard the typed input (do **not** run it), reset `historyCursor`, then one `freshPrompt()`. Empty input still freezes `$ ^C` + one prompt.

### `freezeInput(suffix?)` helper

The Enter-branch line tear-down (live input → static echoed text: strip `contenteditable`/`role`/`aria-multiline`/listeners/`shell-input` class, drop the block cursor) was **extracted** from the inline Enter logic into a shared `freezeInput(suffix = '')` helper, reused by both Enter (commit, no suffix) and Ctrl-C (cancel, `'^C'` suffix) so the freeze semantics can never drift between them. The optional `suffix` is appended to the echoed text.

(Pre-existing observation surfaced during `by18`, out of scope and harmless: `freezeInput` has always left the `data-terminal-prompt` attribute on the frozen line — since `9vbo`, because `freshPrompt` sets it on every live line. The one-trailing-prompt invariant is properly characterized by the **single contenteditable input** being the session's last line; every live-prompt lookup goes through `input.closest('[data-terminal-prompt]')`, never a bare attribute query, so stale attributes on frozen lines are never matched.)

## Above-the-fold activation pass (change `23xc`)

On a common ~1280×750 laptop viewport the live prompt sat **below the fold** (baseline measurement: Starlight's splash hero `padding-block` resolved to ~91px each side; the live prompt landed at y≈876 against a 750px fold) — the terminal, the site's signature interaction, read as a decorative screenshot. Change `23xc` makes the interactivity discoverable with three combined levers, all activation-time, zero new dependencies, `index.mdx` byte-identical. It explicitly sequences **before** the queued polish items `[by18]` (touch), `[cuur]` (command UX + a11y), `[o33t]` (delight) — they polish a surface visitors must first be able to see.

### Hero rhythm tightening (CSS-only, splash-scoped)

`terminal.css` overrides scoped via **`[data-has-hero]`** — Starlight's own splash-page attribute on `<html>`, present on hero pages only — so doc pages render with unchanged spacing, and the extra attribute outranks Starlight's `:where()`-scoped component rules without `!important`. Values: `.hero` `padding-block: 3rem 1.5rem`, `.hero .stack` `gap: 1.5rem`, `.terminal-window` `margin-top: 0.75rem` (tuned by in-browser measurement at 1280×750). The base `.terminal-window`/`.shell-session` margin rules still apply on non-hero pages — they are not shadowed.

### Resting-state top anchor (scroll geometry, not content)

Until the first prompt-emitting interaction the session viewport is **top-anchored**: the greeting line is the first visible line, the live `$` prompt sits directly below it, and the boot transcript stays in the DOM above, reachable by scrolling up — exactly like a real terminal after `clear`.

- `anchorToGreeting(greetingEl)` computes the greeting's offset within the scrollable session (bounding-rect delta + `scrollTop` − the session's top padding) and assigns `session.scrollTop` directly — instant, no smooth scrolling (trivially motion-safe). A `scrollTop`-only approach is **mathematically insufficient**: the content below the greeting (~2 lines) is far shorter than the ~325px viewport, so max scroll (≈108px) cannot reach the greeting's offset (≈400px). The function therefore extends the session's **inline `padding-bottom`** by exactly the deficit — the blank rows a real terminal shows after `clear`. This is scroll geometry, not content: the live prompt remains the session's **last DOM child**, so the exactly-one-trailing-prompt invariant is untouched.
- **Re-anchored once after `document.fonts.ready`** (JetBrains Mono loads async and shifts line metrics), guarded on still-`resting` AND the user not having scrolled away from the anchored position (`|scrollTop − anchoredScrollTop| < 2`) — never yanking a user-initiated scroll.
- **`exitResting()`** — called from every prompt-emitting path: `commitLine` (Enter and, since `by18`, command-bar chip taps) plus the Ctrl-L and Ctrl-C branches of `onKeydown` — flips the `resting` flag and clears the inline filler; the original bottom-pinned behavior (`scrollToBottom` after `print`/`freshPrompt`) resumes unchanged for the rest of the session.
- **No-JS**: the static transcript renders at browser-default `scrollTop = 0` exactly as before — the anchor is island-only.

### Activation-time greeting line

Printed by the island at activation — after `promptLine.remove()`, before `freshPrompt(false)` — one dim line (classes `shell-out shell-dim`, named `GREETING` constant):

```
seven small CLIs that force agents to plan first. type 'help' or 'ls'.
```

The copy deliberately omits the literal "shll" / the verbatim hero tagline — the tagline renders directly above the terminal in the tightened hero, and the shorter copy keeps the tail invitation (`type 'help' or 'ls'.`) visible under the session's `white-space: pre` on narrower laptops. Island-printed only: the static no-JS transcript stays byte-identical (the progressive-enhancement source of truth).

### Idle ghost hint (one-shot, visual-only)

A one-shot timer (`HINT_DELAY_MS = 4000`) armed at activation. After 4 s without interaction, `showIdleHint()` appends a **visual-only** `aria-hidden="true"` span (class `shell-ghost`, copy `HINT_TEXT`) to the live prompt line **after** the block cursor, fish-autosuggestion style: `$ ▊try 'ls' ⏎`.

- It is never inside the contenteditable input — never part of the textbox's accessible name/value, can never be submitted by Enter, and **never focuses the input** (the deliberate `9vbo` no-autofocus decision stands — the hint draws the eye, it does not steal focus).
- Types in character-by-character via `setInterval` (`HINT_TYPE_MS = 70`) editing the span's `textContent` in place — deliberately NOT `print()`/`scrollToBottom()`, so the typing never moves the scroll position. Under `prefers-reduced-motion: reduce` (checked via `window.matchMedia`) the full text appears statically — no typing interval, still dim, still dismissable.
- `dismissIdleHint()` is a one-shot latch (`hintSpent`): interaction **before** the timer fires cancels it; **after**, it removes the span and clears a mid-animation interval; either way the hint never returns this page view (no re-arm, no storage — it returns on the next page load until the visitor interacts). Wired as the **first statement of `onKeydown`** (before branch dispatch, so Tab as the very first keystroke dismisses the ghost before completion logic runs), into `onFocus`, and at the top of the terminal-surface `onClick` before its link/selection early-returns (a link click or in-progress text selection still counts as interaction).
- Skin: `.shell-ghost` is `color: var(--c-fg-faint)` + `user-select: none` — both themes for free via the shared variable.

### Pre-existing autofocus bug fixed

Baseline measurement found `document.activeElement` was the live input **on page load**: `freshPrompt`'s unconditional `caretToEnd()` placed a selection range inside the contenteditable, which gives it focus in Chromium — silently violating the documented `9vbo` no-autofocus decision. `caretToEnd()` is now **gated to the focusing path** (`focus = true`); the click-to-focus and Tab paths re-place the caret themselves. The implementation now matches the documented invariant (typing before clicking/tabbing no longer reaches the input — the documented intended behavior).

## Touch support (change `by18`)

Before `by18` the terminal was keyboard/click only — on phones the interaction `23xc` made visible above the fold didn't work (the idle hint taunts `try 'ls' ⏎` at users who can't type it). Change `by18` adds two complementary levers — tap-to-focus hardening and an on-screen command bar — both island-only, zero new dependencies, `index.mdx` byte-identical.

### Tap-to-focus rides the synthesized click (no parallel touch path)

Browsers synthesize a `click` after a tap on non-interactive elements, and `focus()` inside that handler is gesture-qualified — it summons the soft keyboard on iOS Safari / Android Chrome. So tap-to-focus reuses the **existing `onClick` surface handler**, hardened with **`touch-action: manipulation` on `.terminal-window`** (`terminal.css`): drops the double-tap-to-zoom heuristics that can delay or swallow the synthesized click, and prevents accidental zoom on rapid chip taps — pan/scroll gestures unaffected, no behavior change for mouse users. A `touchend` fallback was **deliberately NOT built**: the intake mandated verify-first, not speculative code, and Chromium touch-emulation verification passed 40/40 Playwright checks (tap focuses the input via `activeElement`, link taps still navigate, chips dispatch, media-query visibility, keyboard operation, idle-hint/resting interplay). The existing bails (links, active text selection) keep working under touch; a third bail was added for the command bar (below).

### Shared commit path: `commitLine(focusNext)`

The Enter-branch commit sequence in `onKeydown` — `exitResting()` → read+trim the raw line → `freezeInput()` → empty-line short-circuit (fresh prompt only) → `ignoredups` history push + `saveHistory()` → `historyCursor` reset → `run(raw)` → exactly one `freshPrompt(focusNext)` — was **extracted** into a shared `commitLine(focusNext: boolean)` helper (same extraction precedent as `freezeInput(suffix?)` in `n23o`). Enter calls `commitLine(true)` (focus follows command execution — the desired keyboard behavior); the chip path calls `commitLine(false)`. Every committed line — typed or tapped — flows through one sequence, so commit semantics can never drift and the exactly-one-trailing-prompt invariant holds **by construction** on the chip path.

### On-screen command bar (touch-primary devices only)

`injectCommandBar()` runs at activation (after the click-surface wiring) and appends a `.terminal-cmdbar` (`role="group"`, `aria-label="quick commands"`) as the **last child of `.terminal-window`** — below the `pre.shell-session` scroll viewport, reading as a keyboard-accessory row on the terminal's bottom edge, adjacent to where the OS keyboard rises. It holds four native `<button type="button">` chips whose `data-cmd` comes from the module-scope **`CHIP_COMMANDS`** roster (`ls`, `help`, `version`, `install` — `install` included because it is the site's primary CTA; the chip dispatches the existing command's **real** `/getting-started/install/` navigation). One **delegated** `click` listener on the bar (`onChipClick` resolves `closest('button.terminal-chip')`), not four per-button listeners.

- **Island-injected, never static markup** — with JS off the chips would be dead buttons, violating the progressive-enhancement boundary (greeting-line precedent, `23xc`); `index.mdx` stays byte-identical. If the `.terminal-window` wrapper is absent the bar is **skipped gracefully** (no throw; tap-to-focus unaffected — chips appended inside the `pre` would corrupt the transcript stream).
- **Living OUTSIDE `pre.shell-session`**, the bar leaves the resting-state top anchor, the `scrollToBottom` geometry, and the live-prompt-last-DOM-child invariant untouched.
- **A chip tap = full interaction semantics**: `dismissIdleHint()` (a one-shot latch, so the surface handler's own dismissal can never double-fire) → set the input text to `data-cmd` → `commitLine(false)`. Chip-run commands enter the same `history[]` (↑/↓ recall and the `history` command see them; `ignoredups` + sessionStorage apply identically).
- **The chip path does NOT focus the input** (`focusNext = false` — load-bearing): focusing would summon the soft keyboard over the output the user just asked for; a chip user is in touch mode, and the keyboard appears only when they tap the prompt itself. To keep that true against event bubbling, the window-surface `onClick` gained a `.terminal-cmdbar` **early-return bail** (placed after `dismissIdleHint()`, mirroring the existing link bail) so the bubbled chip click never reaches the focus affordance.
- **Visibility is CSS-only**: `.terminal-cmdbar { display: none }` by default, revealed as a wrapping flex row only under `@media (hover: none) and (pointer: coarse)` — the touch-primary signal. The bar shows on phones/tablets at any width and **never on desktop** (narrow desktop windows keep the full keyboard affordances; "not appear on desktop" was chosen over "render but redundant").
- **Skin via `--c-*` only** (Constitution V, both themes for free): `var(--c-surface)` bar with a `1px solid var(--c-border)` top border (the titlebar's chrome language); transparent bordered chips with `var(--c-fg)` text, `font: inherit` (buttons don't inherit the mono font) and `cursor: pointer` (overriding the surface's `cursor: text`); `:active` → `var(--c-surface-2)`; visible `:focus-visible` outline in `var(--c-accent)`. No animation — nothing new to gate behind `prefers-reduced-motion`.

## Command polish & accessible output (change `cuur`)

After `23xc`/`by18` made the terminal discoverable and reachable, the command experience itself still had rough edges (a typo dead-ended; `help` was all-or-nothing; `cd` yanked you off the page on the same tick as Enter) and everything `print()` appended was **silent for screen-reader users** — a WCAG 4.1.3-shaped failure on the site's signature feature. Change `cuur` is the core-polish pass the backlog sequences before `[o33t]` (delight): five small, additive levers in the island + one stylesheet block + one new lib module, zero new dependencies, `index.mdx` byte-identical.

### Did-you-mean suggester (`src/lib/terminal-suggest.ts`)

A new **dependency-free** module exporting `damerauLevenshtein(a, b): number` and `suggestCommand(input, candidates): string | null`. Extracted to `src/lib/` (NOT inlined in the island) so it is unit-testable under the existing `node --test scripts/*.test.mjs` pattern; Vite bundles it into the client island.

- **Algorithm**: Damerau-Levenshtein in its **optimal-string-alignment** form — an ADJACENT TRANSPOSITION counts as 1 edit, so the classic fat-finger typo class (`hlep`→`help`, `verison`→`version`) scores 1 where plain Levenshtein would score 2 (and would miss them at the short-input threshold). Full (m+1)×(n+1) matrix — inputs are command tokens, so it's cheap.
- **Threshold**: max distance **1 when `input.length <= 3`, else 2** — the short-input clamp stops absurd matches like `vi`→`cd` (distance 2 on a 2-char token is a different word, not a typo). Input is lowercased before matching.
- **Tie-break**: lowest distance wins; on equal distance, the EARLIER candidate in iteration order wins (a strict `<` comparison — a later candidate only displaces a strictly closer one). No candidate within threshold → `null`.
- **Candidates at both call sites**: `Object.keys(COMMANDS)` — hidden eggs INCLUDED (a near-miss egg like `forune`→`fortune` rewards the curiosity the `help` footer invites; the list itself still never reveals them). Single source of truth for "what is a command".
- **Wiring in `run()`'s not-found branch**: a suggestion replaces the `type 'help'` tail on the same line (`command not found: instal — did you mean 'install'?`); `null` keeps the existing line unchanged.
- **Unit-tested**: `scripts/terminal-suggest.test.mjs` (`node --test`, native TS type-stripping import of the `.ts` module — same pattern as `extract-readme.test.mjs`), 11 tests pinning the contract: transposition=1, classic Levenshtein cases, the acceptance pair `instal`→`install`, an egg candidate (`forune`→`fortune`), the short-input clamp (`vi`→`null`, `lss`→`ls`), distance 2 for >3-char inputs, no-match→`null`, both tie-break directions, lower-distance-beats-order, and lowercasing.

### `help <command>` — argument-aware help

A module-scope `HELP_DETAIL: Record<string, Line[]>` (built by a `helpDetail(usage, detail)` factory beside `SYNOPSIS`) carries per-command detail in the man-page shape: one usage line (`shell-out`) + one dim elaboration line (`shell-out shell-dim`), both indented. **EVERY key in `COMMANDS` has an entry — listed commands AND hidden eggs**: `help sudo` answers once you've found `sudo`, but the bare list never enumerates the eggs (answering a direct question is not advertising — the discovery ethos stands).

- **Dispatch**: bare `help` prints the existing short list UNCHANGED (detail lives behind the argument, so the list stays scannable); `help <arg>` resolves via `helpFor(arg.toLowerCase())`.
- **`helpFor` resolution order** (deliberate): `HELP_DETAIL` lookup first — so `shll` (both a command and a tool) lands on its command entry, never the tool branch — then the tool check, then the suggester.
- **Tool name** (in `TOOLS`, no command entry): points sideways — `help: no help for 'hop' — try 'man hop'` (tools are documented by `man`, not `help`).
- **Unknown arg**: `help: no help for 'xyz'` + the same suggester tail as the not-found branch when a candidate exists (`— did you mean '…'?`) — one matcher, two call sites, no second fuzzy-match implementation to drift.

### Intentional navigation beat (`navigateWithBeat`)

`cd`/`open`/`install` previously called `window.location.assign` synchronously on Enter — instant navigation off a playful exploration surface read as a misclick, yanking the visitor away before the `opening …` line even registered. One shared helper `navigateWithBeat(route, lines)` now serves all three:

1. Prints the context lines first — `cd`/`open` prepend the tool's `SYNOPSIS` line ("context before motion"); `install` keeps its single line — then `opening <a href>{route}</a> … (Ctrl-C to cancel)` as a **real clickable anchor** (`html: true`, the same trusted-static-string pattern as `man`/`ls`; classes `shell-out shell-dim`, today's `opening` skin).
2. Schedules `window.location.assign(route)` via `window.setTimeout` with **`NAV_BEAT_MS = 900`** (a named constant beside `HINT_DELAY_MS`).
3. **Ctrl-C cancels**: the pending timer id (`pendingNav`) lives at `initTerminal` scope; the existing Ctrl-C branch in `onKeydown` clears it before `freezeInput('^C')` — `^C` + a fresh prompt then read exactly like aborting a command in a real shell, and you stay on the page. This is what makes the beat *intentional* rather than laggy.
4. The clickable anchor is the impatient path (click through immediately); chip taps (`install` chip, `by18`) flow through `commitLine → run → navigateWithBeat` and inherit the beat + tappable link (touch users have no Ctrl-C but gain the anchor).
5. **`pendingNav` is deliberately NOT cleared by `commitLine`** — a new command committed during the beat lets the scheduled navigation fire (accepted + documented in a code comment: the beat is short and the printed line already said where it's headed). Known deferred nice-to-have: a nav-during-beat does not clear the *previous* nav's timer either (a second `cd` within 900 ms briefly holds two timers — harmless in practice since the first navigation unloads the page; `o33t` shipped without this tightening, so it remains open).
6. The beat is a pure `setTimeout` — **timing, not animation** — so there is no `prefers-reduced-motion` interaction.
7. Empty/invalid `cd`/`open` args short-circuit with usage / `no such tool` BEFORE the helper — no timer is ever scheduled.

### `aria-live` output announcements

At activation — island-only; the no-JS static transcript is inert and needs nothing — the island sets **`aria-live="polite"` + `aria-atomic="false"` on `pre.shell-session`**, BEFORE the greeting prints (so the greeting announces once on load — the right SR introduction to an interactive region). Everything appended by `print()`/`printBeforePrompt()` is thereafter announced after the user's keystroke settles; `atomic=false` announces only the appended nodes, never re-reads the whole transcript.

- **Noise control**: `freshPrompt()` marks each new prompt's `$` span (`.shell-prompt`) **`aria-hidden="true"`** — every fresh prompt line is an appended node, so an exposed `$` would be announced after every command. The input's existing `aria-label` already carries the prompt semantics; the block cursor span was aria-hidden already.
- **What stays silent, by construction**: the aria-hidden idle ghost hint (hidden additions aren't announced); `clear`/Ctrl-L (`replaceChildren` removals aren't announced). The Ctrl-C `^C` suffix IS a text addition — announcing it is correct cancel feedback.
- **Known accepted trade-off**: screen readers may announce typed characters twice (once as typing echo, once if the frozen echo line registers as an addition). A parallel visually-hidden mirror region was **rejected at intake** (duplicate DOM, drift risk; user-confirmed, intake assumption #6) — the session `pre` itself is the live region.

### Backlog-constraint deltas (conscious, intake-encoded)

The `[o33t]` backlog entry forbade fake network, fake filesystem, and streaming gags. Resolution, decided by the user against the tier analysis that flagged the conflict:

- **No fake network — honored**: `curl`/`wget` explicitly DENY network access.

### `FAKE_ENV` — one record for `env` and `echo`

Module-scope `FAKE_ENV: Record<string, string>` with exactly eight pairs (`SHELL=/bin/shll`, `USER=visitor`, `HOME=/home/visitor`, `EDITOR=spec`, `PLAN=first`, `AGENTS=7`, `PATH=/plans:/specs:/code`, `TERM=shll-256color`). `env` prints them `KEY=value` in declaration order; `echo` now prints `expandVars(ctx.raw, FAKE_ENV)` (`echo $SHELL` → `/bin/shll`; unknown var → empty, authentic) — one source, no drift. `HELP_DETAIL.echo`'s detail line mentions the expansion.

### Pure-logic lib (`src/lib/terminal-eggs.ts` + `scripts/terminal-eggs.test.mjs`)

The cuur `terminal-suggest.ts` pattern again: dependency-free logic in `src/lib/` (Vite bundles it into the island), pinned by a `node --test` suite (22 tests, native TS type-stripping import) covering `$NAME`/`${NAME}`/unknown-var expansion, seq arity/validation/empty-range/reverse/zero-increment, every `classifyRm` class including flag-order variants (`-fr /`), `classifyTar` survivor/bomb edges, and the prototype-chain pin (`$constructor`/`${__proto__}`/`$toString` → `''`).

- `expandVars(text, env)` — `$NAME` and `${NAME}` (`[A-Za-z_][A-Za-z0-9_]*`); unknown name → `''`; no `$$` escaping (documented limitation).
- `seqLines(args): string[] | null` — GNU `seq LAST | FIRST LAST | FIRST INCR LAST`, integers only; `null` on non-integer/wrong-arity/zero increment; EMPTY array for an empty range (authentic — real seq prints nothing); generation bounded by exported **`SEQ_GEN_CAP = 10000`** so `seq 1 1000000000` cannot freeze the tab — the island displays at most `SEQ_CAP = 100` lines and keeps the cap comment honest with a `+` suffix when generation truncated the true total.
- `classifyRm(args): 'missing' | 'refuse' | 'guarded-root' | 'deluxe'` — recursive detected ordering-free (`/^-[a-su-z]*r/i` or `--recursive`: `-r`, `-rf`, `-fr` all count), root target = literal `/` or `/*`, deluxe additionally requires `--no-preserve-root`.
- `classifyTar(args): 'survivor' | 'bomb'` — survivor = first arg a letters-only flag cluster (optionally `-`-prefixed) containing `f` plus one of `c`/`x`/`t`.

### The `Object.hasOwn` own-property-guard idiom (review-cycle lesson, load-bearing)

A plain-object record keyed by **user input** must never be read bare: an unguarded `record[name]` walks the prototype chain. Pre-rework, `echo $constructor` printed Object's source, and `man constructor` / `help constructor` / a bare `__proto__` command returned an inherited, truthy, non-conforming member — `print()` threw BEFORE `freshPrompt` could run, leaving the terminal with **zero prompts** (bricked until reload — the one-trailing-prompt invariant's worst failure mode). Review cycle 1 added `Object.hasOwn(record, key) ? record[key] : undefined` at **all four** user-keyed lookups — `expandVars`'s env read, the `man` `HELP_DETAIL` bridge, `helpFor`, and `run()`'s `COMMANDS` dispatch — so prototype-chain names hit the normal not-found branches. One idiom at all four sites (ES2022, comfortably in-baseline; no `hasOwnProperty.call` fallback). **Any future record lookup keyed by user input MUST use this guard.**

### The line streamer (Tier C engine)

`initTerminal`-scope `activeStream` (interval id) + `streamFollowup` (pending onDone timer, the rm-deluxe beat) with `startStream(lines, { intervalMs, onDone? })` / `stopStream()`, living beside cuur's `pendingNav`. The contract:

- **At most one stream**: `startStream` first calls `stopStream()`.
- Lines are emitted **one per tick via `printBeforePrompt()`** — output lands above the live prompt, so the exactly-one-trailing-prompt invariant holds **by construction** (the Tab ambiguous-listing precedent). `onDone` (if any) runs after the last line.
- **Reduced motion**: no interval — all lines print at once and `onDone` runs immediately (the `23xc` ghost-hint precedent: streams are timing, but their visual effect is motion; reduce gets the content without the cadence).
- **Three kill paths**: the **Ctrl-C** branch calls `stopStream()` beside its `pendingNav` clear (the frozen `^C` + fresh prompt + halted output read exactly like killing a foreground process); the **Ctrl-L** branch calls it (wiping a screen `yes` keeps flooding would un-clear it instantly; the `clear` command inherits the same kill via commitLine); and **`commitLine`** calls it before `run()` — placed AFTER the empty-line short-circuit, so a bare Enter during `yes` does NOT kill the stream, just like a real shell. `stopStream()` clears BOTH ids, so Ctrl-C aborts the rm-deluxe followup beat too.
- **Deliberate contrast with `pendingNav`**: `commitLine` kills streams but does NOT clear `pendingNav` — the nav beat is 900 ms and already announced its destination; streams are long-lived and would interleave with the new command's output. The asymmetry is documented at both sites.
- Frame lines typically carry `ariaHidden: true`; the closing summary line is announced. The one exception: `tail`'s log lines are announced (slow cadence, meaningful content).

**`printBeforePrompt` gained a no-live-prompt append fallback** (gated on `input.isContentEditable`): reduced-motion streams run synchronously inside `run()`, when the previous input is frozen but still carries its stale `data-terminal-prompt` attribute — a bare `closest()` lookup would insert output ABOVE the just-echoed command. With no LIVE prompt the function appends, exactly where `print()` would land the line. Two supporting extractions: `makeLineEl(ln)` (line-element construction shared by `print()` and `printBeforePrompt()` — where `ariaHidden` is honored) and `prefersReducedMotion()` (one media-query helper for the streamer, `yes`, rm-deluxe, and the `23xc` ghost hint, refactored onto it).

### `Line.ariaHidden` and the announcement policy

`Line` gains an optional `ariaHidden?: boolean`; `makeLineEl` sets `aria-hidden="true"` on the element when true. Policy: **ASCII art and rapid stream frames are announcement garbage** to the cuur live region — each art/animated command hides its frame/art lines and announces exactly **one readable summary line** instead. Retrofit of existing commands (same mechanism): the `shll` splash's 5 art rows are now `ariaHidden: true` (the pitch + tip stay announced) and `sl`'s 7 locomotive rows live in one `aria-hidden` container (the punchline stays announced) — correcting SR announcement noise that had existed since the live region landed in `cuur`.

### Tier C specifics

- **`yes [text]`** — streams `y` (or the raw arg) at `YES_TICK_MS = 150`, frames `ariaHidden`, hard-capped at `YES_CAP = 50` with the announced stopped comment ("Ctrl-C would have been faster — and more satisfying"); Ctrl-C mid-stream halts with no extra line (the `^C` echo is the feedback). Reduced motion: `YES_REDUCE_COUNT = 7` hidden lines at once (a seven-tools wink) + the announced "imagine it" variant. Teaching value: makes the `n23o` Ctrl-C affordance discoverable.
- **`sl` upgrade** — the 7 art rows ride an `aria-hidden` `.shell-art-train` > `.shell-train-inner` wrapper animated by `@keyframes shell-train` (3 s linear, `translateX(100%)` → `translateX(-105%)`, forwards) in `terminal.css`; a JS `animationend` listener removes the container — the train has left; the announced punchline remains. The train selector joined the EXISTING reduced-motion gate block with `animation: none`: static art, `animationend` never fires, the art stays. Motion-safety purely CSS, no JS branch. (Accepted: on very wide viewports the train is partially visible at t=0 — translateX percentages are relative to the inner element's own width.)
- **`tail`** — missing/wrong-file args hit authentic error branches + a dim `(try: tail -f agents.log)`; `tail agents.log` (with or without `-f`) streams the fixed 8-line `AGENT_LOG` const at `TAIL_TICK_MS = 700`, **announced**, timestamps static `13:37` literals (leet o'clock), the last log line and the closing `shell-comment` self-identifying the site as static (the no-implied-runtime mitigation in action).
- **rm-deluxe** (`classifyRm` = `deluxe`, i.e. `rm -rf / --no-preserve-root`) — streams one announced `removing /tools/{tool}` line per `TOOLS` entry (canonical order) + `removing /home/visitor` at `RM_TICK_MS = 300`; `onDone` **wipes the transcript** via `session.replaceChildren(liveLine)` where `liveLine = input.closest('[data-terminal-prompt]')` — the live prompt element is **preserved in place** (one-trailing-prompt invariant holds, listeners survive, no `freshPrompt()` needed) — with a **conditional focus restore**: `replaceChildren` detaches-and-reinserts the live line, and detaching blurs a focused element, so the handler captures `document.activeElement === input` before the wipe and restores `input.focus()` + `caretToEnd()` after it ONLY when the input held focus (the no-autofocus principle stands — a chip-tap deluxe never focused the prompt and must stay that way). After a `RM_BEAT_MS = 900` beat held in `streamFollowup` (cancelled by `stopStream()`, so Ctrl-C aborts the whole sequence cleanly at any stage), the two resolution lines print; the greeting is NOT re-printed — the lost transcript is the consequence and the joke. Reduced motion: removal lines at once, the wipe is **SKIPPED** (a sudden full-screen wipe is exactly the dramatic visual change reduce users opted out of), resolution immediate with the merciful `(transcript spared. reduced motion is mercy.)` second line.

### Constants

All cadences/caps are named constants following the `HINT_*`/`NAV_BEAT_MS` convention: `YES_TICK_MS = 150`, `YES_CAP = 50`, `YES_REDUCE_COUNT = 7`, `TAIL_TICK_MS = 700`, `RM_TICK_MS = 300`, `RM_BEAT_MS = 900`, `SEQ_CAP = 100` (island) and the exported `SEQ_GEN_CAP = 10000` (lib).

### Output shape

Opening line `the full roster — you found it.` (`shell-out`); then for each group a blank separator line, a dim category header (`shell-out shell-dim`), and one or more two-space-indented ` · `-joined command lines (`shell-out`); then a blank line and the closing `(each one: help <command>)` (`shell-comment` — per-command depth stays behind `help <command>`; the sheet maps the territory, that closing line is the zoom). The five fixed category names, in order: **`navigate`** (ls, cd, open, install, version, theme, clear, history, help, cheatsheet — it lists itself after `help`; a key must be covered somewhere, and `help` lists `help`), **`look around`** (pwd, uname, id, date, uptime, env, ps, whoami), **`do things (try to)`** (rm, mkdir, touch, mv, cp, chmod, chown, sudo, kill, curl, wget — curl/wget try network things and get refused, exactly like the file-op refusals beside them), **`classics`** (make, diff, tar, vim, emacs, nano, less, yes, sl, tail, fortune, true, false, exit, shll), **`real utilities`** (echo, seq, grep, sha256sum, man). Display strings decorate beyond the bare key where the decoration teaches the interesting invocation: `cd <tool>`, `make plan`, `diff plan reality`, `tail -f agents.log`, `echo $VAR`, `grep <pattern>`, `sha256sum <text>`, `man <thing>`. All lines are **announced** — static meaningful text through the normal `print` path, no `ariaHidden` (the `tail` precedent for announced content); the exactly-one-trailing-prompt invariant is untouched (no new prompt-emitting path).

### The anti-drift contract (load-bearing)

Group membership lives in **one `CHEATSHEET_GROUPS` const** beside the island's other named rosters (`FAKE_ENV`/`CHIP_COMMANDS`), entries `{ key, display? }`; **`CHEATSHEET_ALIASES`** declares the alias-of keys (`vi → vim`, `more → less`, `:q → exit`) — they render with their primary's entry and are never listed on their own, but still count as covered. The handler **recomputes coverage at runtime on every run** via `buildCheatsheet(CHEATSHEET_GROUPS, CHEATSHEET_ALIASES, Object.keys(COMMANDS))`:

- **`covered`** = every group entry key ∪ every alias key; **`missing`** = `COMMANDS` keys not in `covered` → appended as a final **`uncategorized`** group (bare keys, `COMMANDS` declaration order, the exported `UNCATEGORIZED` const). A future `COMMANDS` key can never silently vanish from the sheet — forgetting to categorize degrades to an honest `uncategorized` listing, never a silent omission.
- **Stale-entry tolerance**: a group entry whose key is no longer in `COMMANDS` is dropped at render; a group whose entries are *all* stale is omitted entirely (no orphan dim header over nothing).
- **Every key covered exactly once**: alias-of keys fold into their primaries; true pairs (`cd · open`, `curl · wget`, `true · false`) display both names adjacent as separate entries.
- The lib takes `commandKeys: string[]` (the island passes `Object.keys(COMMANDS)`, which returns **own properties only**) — so the o33t own-property guarantee holds by construction, with no `Object.hasOwn` needed inside the pure lib.

### Width-budget chunking

`chunkLine(tokens, sep, maxWidth)` greedily packs the ` · `-joined entries into lines of at most **`CHEAT_LINE_WIDTH = 74`** joined chars (+ the 2-space indent = 76 total) under the session's `white-space: pre` — the GREETING horizontal-scroll precedent. A token is **never split**; an over-budget token gets a line of its own; empty input yields no lines. The 74 budget reproduces the user-approved preview's classics chunking exactly (first line ends at `sl` at exactly 74 joined chars); navigate (10 entries, 87 joined chars) wraps by the same single greedy rule (first line ends at `help`, `cheatsheet` on the wrap line) — one rule, no special-casing. `CHEAT_SEP = ' · '` is the named separator.

### Card shape (the user-approved mock)

### Build-time data path — zero runtime fetches (Constitution I)

`TerminalPrompt.astro`'s frontmatter (comment-only before `37ng`) now does a build-time read:

- **Repo-root ascent** via the shared `repoRootFromModuleUrl` (`src/lib/repo-root.ts` — the VersionTable precedent; a fixed `../..` depth breaks under Vite bundling), then **`readdirSync` over `help/*.json`** — the directory IS the roster (the island's `TOOLS` const is unreachable from frontmatter; a duplicate roster const would be drift risk; a stray extra file adds an unreferenced payload entry, harmless).
- **Per-tool skip-degrade**: unreadable/malformed JSON (`try/catch`) or schema-invalid (`HelpDocSchema.safeParse`) skips that tool only — never a build failure. **Deliberate contrast with `VersionTable`'s build-stop**: VersionTable already build-stops on any missing/invalid rostered doc, so it remains the build's defect gate and the terminal's degrade can never mask a committed defect.
- **Slim payload**: only `{ short, usage, commands: [{ name, short }] }` per tool, keyed by slug, for all 7 tools (the `text` fields are KBs each — hop's alone ~4KB — and the card renders none of them). The normalizations below are applied here, build-time.
- **One template element**: the serialized payload (with `<` escaped to `\u003c` — standard embedded-JSON hygiene, a script element can never be terminated early) is emitted as ONE `<script is:inline type="application/json" data-terminal-help set:html={toolHelpJson} />` in the component's own template — `index.mdx` stays byte-identical (data script elements don't render).
- **Guarded island parse**: `loadToolHelp()` locates the element by the data attribute and `JSON.parse`s at activation (the `versionRowsHtml` capture-at-init precedent: build-time truth, island snapshot, no drift), wrapped in try/catch with a non-object check (the sessionStorage try/catch discipline) — absent element / malformed payload → empty record, in which case **every** card degrades. The handler's payload lookup uses the `Object.hasOwn` guard (the o33t idiom — the payload crossed a JSON boundary). A degraded tool's card falls back to `{slug} — {SYNOPSIS[slug]}` + the nav line (2 lines, never a crash, fresh prompt follows).

### Mechanical normalizations (vn39-clean pure transforms)

Two committed help docs carry producer-side quirks the card would render visibly broken:

- `tu`'s `root.usage` is `"Usage: tu [source] [period] [display]"` — `stripUsagePrefix` removes the leading `Usage:` (case-insensitive) so the card doesn't read `usage: Usage: tu …`.

## Accessibility

- The input is a real focusable, keyboard-navigable control: `contenteditable="true"` with `role="textbox"`, `aria-multiline="false"`, an `aria-label`, and `spellcheck`/`autocapitalize`/`autocorrect` off, plus an explicit `paste` handler that forces `text/plain` and flattens newlines (so a multiline/formatted clipboard payload can't distort the single prompt line — robust regardless of `plaintext-only` browser support, a PR-review fix). (No `tabindex` is set — `contenteditable` is the deliberate native-focusable mechanism.)
- **Block cursor, not the OS caret.** The native text-caret is hidden (`caret-color: transparent`) and a trailing `.shell-input-cursor` block (`▊`, reusing the static skin's `.shell-cursor` glyph + `shell-blink`) stands in, so the prompt reads like a TTY rather than a form field. The block blinks only while focused (`.is-active`, toggled on `focus`/`blur`); idle it is dimmed and steady. There is **no** focus-ring box outline (it read as a form field — removed).
- **Click anywhere in the terminal focuses the prompt** (caret to end), matching how a real terminal grabs the cursor. The handler skips clicks on links (let them navigate), skips when text is selected (don't steal a copy-selection), and skips clicks inside the command bar (a chip commit must not summon the soft keyboard — change `by18`); the surface gets `cursor: text` to hint it's typeable.
- The command-bar chips (change `by18`) are native `<button>`s — tap, Enter, and Space all fire `click`, keyboard-navigable for free — with a visible `var(--c-accent)` `:focus-visible` outline; the bar carries `role="group"` + `aria-label="quick commands"`.
- `cd` / `open` / `install` / `man` resolve to **real** `window.location` navigation, never a JS-only dead end — since change `cuur` the first three go through `navigateWithBeat` (a printed clickable anchor + a 900 ms cancellable beat), so the link is also directly tappable/clickable. No-JS users keep the static transcript's working `<a>` links; the enhancement never removes or hides them.
- **Command output is announced to screen readers** (change `cuur`): `pre.shell-session` is an `aria-live="polite"` / `aria-atomic="false"` region set at activation before the greeting prints; each fresh prompt's `$` span is `aria-hidden` so prompts don't announce noise (see § Command polish & accessible output).
- **Reduced motion is respected throughout** (change `cuur`): one `@media (prefers-reduced-motion: reduce)` block in `terminal.css` holds both blink cursors (`shell-blink` terminal cursors, `terminal-blink` doc-page first-paragraph `▊`) steady-visible; the `23xc` ghost hint and the instant scroll writes were already motion-safe.
- **Stream/art output is announcement-controlled** (change `o33t`): ASCII-art rows and rapid stream frames carry `aria-hidden` (via `Line.ariaHidden` or an aria-hidden container) so the live region announces one readable summary per command instead of frame spam; `tail`'s slow, meaningful log lines are the deliberate announced exception. All streams honor `prefers-reduced-motion` (all lines at once, no cadence), the `sl` train joins the CSS reduced-motion gate (static art, never removed), and the rm-deluxe transcript wipe is skipped under reduce.
- The title-bar dots are `aria-hidden` decoration.

- All animated output (change `o33t`) MUST go through the single `startStream`/`stopStream` engine: at most one stream, frames via `printBeforePrompt` (one-trailing-prompt by construction), reduced-motion = all-at-once + immediate `onDone`. Ctrl-C, Ctrl-L, and `commitLine` (after its empty-line short-circuit, before `run()`) MUST kill the active stream AND the `streamFollowup` beat; `pendingNav` keeps its cuur contract (`commitLine` does NOT clear it).
- Every stream (change `o33t`) MUST be finite and end self-identifying as static — no implied runtime (the conscious backlog-delta mitigation); no fake network (`curl`/`wget` deny) and no fake filesystem (file-ops refuse with authentic read-only errors) anywhere.
- Art and rapid stream frames (change `o33t`) MUST be hidden from the live region (`Line.ariaHidden` / an aria-hidden container) with exactly one announced summary/punchline per command; slow meaningful streams (`tail`) stay announced.
- The rm-deluxe wipe (change `o33t`) MUST preserve the live prompt element (`session.replaceChildren(liveLine)`, never a rebuild) and restore focus + caret ONLY if the input held focus before the wipe; reduced motion MUST skip the wipe.
- `seq` generation MUST stay bounded (`SEQ_GEN_CAP`) and the display-cap copy honest (`+` suffix on a generation-cap-truncated total).
- The `cheatsheet` handler (change `cdbr`) MUST recompute coverage at runtime via `buildCheatsheet` over `Object.keys(COMMANDS)`: uncovered keys (not declared in `CHEATSHEET_ALIASES`) MUST surface under a final `uncategorized` group — never a silent omission; stale group entries MUST be dropped at render and all-stale groups omitted (no orphan header). Every `COMMANDS` key is covered exactly once (alias-of keys fold into their primaries).
- The bare-`help` footer-tip splice (change `cdbr`) is THE one sanctioned change to `help` output — the curated list MUST NOT grow (`cheatsheet` stays unlisted there; the eggs-stay-unlisted ethos is unchanged), and `HELP_DETAIL.cheatsheet` + the `COMMANDS` key MUST stay appended after all existing keys (the suggester tie-break convention).
- Sheet command lines (change `cdbr`) MUST chunk to the `CHEAT_LINE_WIDTH = 74` joined-char budget (+2-space indent = 76 total under `white-space: pre`, the GREETING precedent) via `chunkLine`, which never splits a token; the handler MUST return plain announced `Line[]` through the normal `print` path (no stream, no nav, no `ariaHidden`, no new prompt-emitting path).
- A bare tool name or binary alias (change `37ng`) MUST print that tool's card mechanically sourced from `help/<slug>.json` — header from `root.short` (NEVER the hand-written `SYNOPSIS`, which stays `man`/`cd`'s voice), dim usage, padded subcommand lines capped at `TOOLCARD_SUB_CAP` with the `(+N more — see commands)` tail, and the nav line with real overview/readme/commands/install anchors. The card MUST inform in place — no navigation, no timer, no nav beat; `cd`/`open`/`man`/`install` and `TOOL_ARG_COMMANDS` stay untouched (bare name informs, `cd` navigates).
- The tool-card data path (change `37ng`) MUST be build-time only (Constitution I): the frontmatter enumerates repo-root `help/*.json` via `readdirSync` + the `repoRootFromModuleUrl` ascent (never a duplicate roster const), validates per tool with `HelpDocSchema.safeParse`, and skips a missing/invalid doc without failing the build — `VersionTable` remains the build's defect gate. The slim payload (`{short, usage, commands[].{name,short}}` only — never the KB-scale `text` fields) ships in exactly ONE `data-terminal-help` `application/json` template element with `<` escaped; the island parse MUST be guarded (absent element / malformed / non-object → empty record) and the payload lookup MUST use `Object.hasOwn`; a degraded tool falls back to its `SYNOPSIS` line + nav line, never a crash.
- All card width math (change `37ng`) MUST live in `terminal-toolcard.ts` — every card line, header included, clamped to `TOOLCARD_LINE_WIDTH = 76` with ellipsis truncation; descriptors carry final rendered text (incl. the 2-space indent) and the island maps `kind` → classes only, pinned by `scripts/terminal-toolcard.test.mjs`.
- The `stripUsagePrefix`/`stripToolPrefix` normalizations (change `37ng`) MUST stay pure transforms of json data (vn39-clean — no hand-written prose), applied build-time in the frontmatter where the binary name is known; `buildToolCard` re-applies only the idempotent usage strip.
- The eight `37ng` keys MUST stay appended after `cheatsheet` in BOTH `COMMANDS` and `HELP_DETAIL`; bare `help` output stays byte-identical (the cdbr footer splice remains the one sanctioned change); the cheatsheet `tools` group stays FIRST with `rk`/`fab` folded via `CHEATSHEET_ALIASES`; `shll` stays in `classics` and keeps its splash (only the nav line appended).
- Zero new dependencies; no `astro.config` change; output stays fully static (Constitution I, IV, VI).

## Design Decisions

- **Client island, not inline `<script>`** (`TerminalPrompt.astro`, imported into `index.mdx`) — matches the `Diagram.astro` precedent, keeps `index.mdx` readable, isolates the behavior. (Intake clarification #14.)
- **Hydration target via `data-terminal-prompt`** on the final `.shell-line` — keeps the static markup the single source of truth; avoids brittle positional "last `.shell-line`" queries.
- **`theme` drives the header `<select>` via a dispatched `change` event** — reuses Starlight's `onThemeChange` (the single sync point for `data-theme` + `localStorage` + picker UI), so the prompt and header toggle never diverge.
- **`version` is sourced from the rendered DOM, NOT a hardcoded constant** — since `#47` the homepage `$ shll version` block is rendered by `<VersionTable/>` (build-time, self-updating from `help/*.json`, incl. the `run-kit → rk` display label). At init the terminal snapshots those already-rendered version rows (`.shell-line`s carrying a `[git]` link → `versionRowsHtml`) and `version` re-prints them verbatim. The terminal and the page can never drift; version bumps / roster-label changes flow through automatically. (Supersedes the original in-script `VERSIONS` constant, removed when `#47` made the block self-updating.)
- **No autofocus on page load** (`freshPrompt(false)` at activation) — avoids stealing focus / scrolling the hero; focus follows command execution only.
- **Block cursor instead of the OS caret** — `caret-color: transparent` + a trailing `.shell-input-cursor ▊` (reusing the static skin's glyph/blink), blinking only when focused. The native I-beam-in-a-box read as a form field; a block reads as a TTY and matches the no-JS `$ ▊`.
- **Click-anywhere-to-focus** — a click handler on the `.terminal-window` (fallback: the session) focuses the live prompt and moves the caret to end, but bails on link clicks and active text selections so it never fights the user.
- **Fixed-height scroll viewport** — the in-frame `.shell-session` has a fixed height and scrolls; the panel doesn't grow with output. Earlier it expanded unbounded, which broke the "terminal window" feel.
- **Eggs are NOT listed in `help`** — named after commands a dev would naturally try, surfaced via a "curious dev might try the obvious ones" hint, for organic discovery.
- **Window chrome reverses `260517-pdsp-terminal-skin`** — see § Terminal window chrome; a within-project design decision (changed context: frame as functional affordance), not a constitutional breach.
- **Single hardcoded `#c2553f` red dot** (not a `--c-*` var) — decorative, `aria-hidden`, muted at 0.55 opacity; judged acceptable on both theme surfaces during review (Constitution V parity is mechanism-agnostic correctness).
- **Tab multiple-match listing uses print-without-freezing** (change `n23o`) — `printBeforePrompt()` a `shell-out` listing line above the still-live input; do NOT freeze or re-emit a prompt. *Why*: cleanest path for the one-trailing-prompt invariant (no commit/re-emit happens) and the caret/input stay put. Uses `printBeforePrompt` (insert before the live prompt line), not `print` (append to end) — the latter would drop the listing below the prompt, breaking the trailing-prompt invariant. *Rejected*: freeze→print→`freshPrompt()`-with-reseed (more code, an extra prompt-emitting path to keep correct).
- **`freezeInput(suffix?)` shared by Enter and Ctrl-C** (change `n23o`) — the Enter-branch line tear-down was extracted into one helper so commit (no suffix) and cancel (`'^C'`) can never drift. *Rejected*: copy-pasting the ~12-line tear-down into the Ctrl-C path (drift risk; god-branch).
- **History persisted in `sessionStorage`, not `localStorage`** (change `n23o`) — session-scoped recall survives a refresh but a new browser session starts clean; single namespaced JSON key (`shll:terminal:history`), all access try/catch-guarded with malformed→`[]` coercion so storage failures degrade silently. *Rejected*: `localStorage` (would persist across unrelated sessions).
- **History recall and the `history` command read one shared array** (change `n23o`) — the ↑/↓ cursor walk and the `history` command both read the `initTerminal`-scoped `history[]`, so the listing and the recall can never disagree (no duplicate source of truth).
- **↑/↓ drive history unconditionally** (change `n23o`) — no caret-boundary gate, because the prompt is enforced single-line (paste flattened, `aria-multiline=false`), so there is no multi-line navigation to preserve.
- **Resting-state filler via inline `padding-bottom`, not a spacer element** (change `23xc`) — the content below the greeting (~2 lines) is far shorter than the viewport, so `scrollTop` alone cannot reach the greeting's offset (max scroll ≈108px vs ≈400px needed at default metrics); extending the session's inline `padding-bottom` by the deficit creates the scroll range while the live prompt stays the last DOM child, visually identical to a real terminal's blank rows after `clear`. *Rejected*: a spacer `<div>` after the prompt (violates the last-child/DOM-order decision; `print()` would append after it), and shrinking the session height (changes the window's size and the no-JS layout).
- **`exitResting()` called explicitly from the three prompt-emitting branches** (change `23xc`) — Enter, Ctrl-L, Ctrl-C in `onKeydown`, the exact paths where bottom-pinning resumes; explicit call sites are clearer than implicit coupling. *Rejected*: piggybacking on `freshPrompt`'s `focus` parameter (implicit, fragile coupling).
- **Ghost dismissal precedes branch dispatch in `onKeydown`** (change `23xc`) — `dismissIdleHint()` is the handler's first statement, so Tab as the very first keystroke dismisses the ghost before completion logic runs.
- **`document.fonts.ready` re-anchor guarded on the user not having scrolled** (change `23xc`) — JetBrains Mono loads async and shifts line metrics, so the anchor is recomputed once after fonts load, but only while still resting and within 2px of the anchored `scrollTop` — never yanking a user-initiated scroll.
- **Greeting copy omits the literal "shll" / verbatim hero tagline** (change `23xc`) — the tagline renders directly above the terminal in the tightened above-fold layout, so `seven small CLIs that force agents to plan first. type 'help' or 'ls'.` avoids verbatim duplication and is short enough that the tail invitation survives `white-space: pre` on narrower laptops. *Rejected*: the intake's longer ~92-char draft (would clip the invitation into horizontal scroll below ~1040px-wide viewports).
- **`caretToEnd()` gated to `freshPrompt`'s focusing path** (change `23xc`, pre-existing bug fix) — placing a selection range inside a contenteditable focuses it in Chromium, so the previous unconditional call silently auto-focused the input on page load, violating the documented no-autofocus decision above; the gate makes the implementation match the documented invariant (the click-to-focus and Tab paths re-place the caret themselves).
- **`commitLine(focusNext)` shared by Enter and the chip path** (change `by18`) — the Enter-branch commit sequence was extracted into one helper (the `freezeInput` precedent) so typed and tapped commands can never drift and the one-trailing-prompt invariant holds by construction. *Rejected*: a parallel chip commit sequence (duplication; a second prompt-emitting path to keep correct forever).
- **Chip taps do NOT focus the input** (change `by18`) — `commitLine(false)`: focusing would summon the mobile soft keyboard over the output the user just asked for; a chip user is in touch mode, the keyboard appears only when they tap the prompt itself. Consistent with the no-autofocus lineage (`9vbo`/`23xc`); a one-parameter flip if ever wrong.
- **Chip-click bail in the surface `onClick` (early return), not `stopPropagation()` in the chip handler** (change `by18`) — the bail (`target?.closest('.terminal-cmdbar')`) follows the handler's existing link-bail pattern and is placed AFTER `dismissIdleHint()`, so a chip tap still counts as interaction while never reaching the focus affordance. *Rejected*: `stopPropagation()` (implicit coupling; silently starves any future surface listeners).
- **Bar island-injected at activation, never static markup** (change `by18`) — with JS off the chips would be dead buttons (PE + accessibility violation); greeting-line precedent (`23xc`). Injection is skipped gracefully when `.terminal-window` is absent — chips appended inside the `pre` would corrupt the transcript stream. *Rejected*: static markup in `index.mdx`.
- **Bar visibility via `(hover: none) and (pointer: coarse)`, not viewport width** (change `by18`) — the touch-primary signal: phones/tablets at any width, never desktop. Narrow *desktop* windows are deliberately excluded (they keep the full ↑/↓/Tab affordances); "not appear on desktop" chosen over "render but redundant".
- **No speculative `touchend` fallback** (change `by18`) — the synthesized-click + gesture-qualified-`focus()` chain is the platform-standard mechanism; verification (40/40 Playwright touch-emulation checks) confirmed it reliable, so the only hardening shipped is CSS (`touch-action: manipulation`). The fallback exists as a documented contingency, not code.
- **One delegated bar listener + named `CHIP_COMMANDS` roster** (change `by18`) — `onChipClick` resolves `closest('button.terminal-chip')` (one listener, not four; matches the island's dispatch-by-lookup style); the roster is a module-scope constant beside `TOOLS`/`FORTUNES` (no magic strings). *Rejected*: per-button listeners; inline string literals.
- **Suggester extracted to `src/lib/`, not inlined in the island** (change `cuur`) — unit-testable under the existing `node --test scripts/*.test.mjs` pattern (native TS type-stripping); Vite bundles it into the island. *Rejected*: inline (untestable without a DOM harness).
- **OSA Damerau-Levenshtein, not plain Levenshtein or prefix matching** (change `cuur`) — the classic typo class (`hlep`, `verison`) is an adjacent transposition: 1 edit under OSA, 2 under plain Levenshtein (missed at the short-input threshold); prefix matching misses transpositions entirely. The short-input clamp (≤3 chars → max distance 1) stops absurd matches like `vi`→`cd`.
- **Eggs ARE suggester candidates and DO answer `help <egg>`, but are never listed** (change `cuur`) — `Object.keys(COMMANDS)` is the single candidate roster for both call sites; a near-miss egg rewards curiosity while the bare `help` list stays short and egg-free (the `9vbo` discovery ethos, extended not weakened).
- **Nav beat = auto-navigate after 900 ms with a clickable anchor + Ctrl-C cancel** (change `cuur`, intake assumption #5, user-confirmed) — keeps the command's promise (it navigates) while giving a visible, cancellable beat; the anchor is the impatient path, Ctrl-C the stay path; a pure `setTimeout` (timing, not animation — no reduced-motion interaction). *Rejected*: link-only / no auto-navigation (breaks the "command does the thing" shell contract).
- **`pendingNav` cleared by Ctrl-C only, never by `commitLine`** (change `cuur`) — a command committed during the beat lets the pending nav fire (accepted + documented in a code comment: the beat is short, the printed line said where it's headed). A nav-superseding-nav timer overlap is a known deferred nice-to-have (`o33t` shipped without it — still open).
- **Live region = the session `pre` itself, `aria-atomic="false"`** (change `cuur`, intake assumption #6, user-confirmed) — announces appended nodes only; the `$` of each fresh prompt is `aria-hidden` to cut per-command noise (the input's `aria-label` carries prompt semantics). Possible SR double-announcement of typed characters is a known accepted trade-off. *Rejected*: a parallel visually-hidden mirror region (duplicate DOM, drift risk).
- **Reduced-motion gate keeps cursors steady-visible, not removed** (change `cuur`) — the block cursor signals typeability, so under `reduce` it stops pulsing but stays rendered: full opacity when `.is-active` (focus still reads as "live"; restated at the base rule's own specificity so the gate isn't outranked), the existing 0.35 idle dim otherwise. Only `animation`/opacity touched — Constitution V parity free via `--c-*`.
- **Streamer on `printBeforePrompt`, never freeze/re-emit** (change `o33t`) — frames land above the live prompt, so the one-trailing-prompt invariant holds by construction (the Tab-listing precedent). *Rejected*: emitting prompts per frame (a new prompt-emitting path to keep correct forever).
- **`commitLine` kills streams but not `pendingNav`** (change `o33t`) — a documented asymmetry: streams are long-lived and would interleave with the new command's output; the nav beat is 900 ms and already announced its destination. The `stopStream()` call sits AFTER the empty-line short-circuit, so a bare Enter during `yes` doesn't kill it — real-shell behavior.
- **`Object.hasOwn` guard on every user-keyed record lookup** (change `o33t`, review rework) — `run()`/`man` bridge/`helpFor`/`expandVars`; prototype-chain names must hit the not-found branches, never inherited members (which threw before `freshPrompt` and bricked the prompt — zero trailing prompts until reload). One idiom at all four sites; no `hasOwnProperty.call` fallback (ES2022 baseline comfortably covers the audience and the Node 22 test toolchain).
- **`printBeforePrompt` no-live-prompt append fallback** (change `o33t`) — gated on `input.isContentEditable` because frozen lines retain a stale `data-terminal-prompt` attribute; synchronous reduced-motion streams would otherwise print ABOVE the just-echoed command. *Rejected*: a parallel reduce-only print path in every stream handler (drift risk).
- **`seqLines` generation bounded by `SEQ_GEN_CAP = 10000` with honest `+`** (change `o33t`) — `seq 1 1000000000` must not freeze the tab; the cap bounds generation and the display-cap comment appends `+` when the total was truncated. *Rejected*: unbounded generation (page freeze); a `{lines, total}` return object (larger contract deviation from the intake).
- **rm-deluxe wipes via `replaceChildren(liveLine)` + conditional focus restore** (change `o33t`) — preserving the live prompt element upholds the prompt invariant without `freshPrompt()`; since `replaceChildren` detach-blurs a focused element, `input.focus()` + `caretToEnd()` run after the wipe ONLY when the input held focus beforehand (chip-tap deluxes stay unfocused — the no-autofocus lineage; `caretToEnd` because a bare `focus()` could land the caret at the start of a mid-stream draft). Reduced motion skips the wipe entirely (the mercy line). *Rejected*: rebuild-the-prompt after a full wipe (a new prompt-emitting path).
- **Announcement policy: art/frames hidden, one summary announced** (change `o33t`) — `Line.ariaHidden` honored in the shared `makeLineEl`; `tail` is the deliberate exception (slow, meaningful frames announced). The `shll`/`sl` art retrofit corrected SR noise dating from the live region's landing in `cuur`.
- **`sl` motion-safety purely in CSS** (change `o33t`) — the crossing animation and its reduced-motion fallback both live in `terminal.css` (`animation: none` in the existing gate block → `animationend` never fires → the art stays); no JS reduced-motion branch to drift. *Rejected*: JS frame redraw (heavier, a second motion mechanism).
- **`true`/`false` print nothing at all** (change `o33t`) — the authenticity IS the egg; the payoff lives in `help true`/`help false`.
- **Shared alias handlers** (change `o33t`) — `editorHandler` (vim/vi), `denyNetwork` (curl/wget), `lessHandler` (less/more): the `exitHandler` precedent, two keys one body. Plus `makeLineEl` and `prefersReducedMotion()` extracted (the ghost hint refactored onto the latter) — the change's own duplication absorbed at apply time.
- **`cheatsheet` complements the Tab dump, never replaces it** (change `cdbr`) — the empty-prompt Tab listing stays as-is (it gains the one new token); the command is the *designed* reveal beside the accidental one. The eggs-stay-unlisted stance is unchanged: bare `help`'s curated list is byte-identical and `cheatsheet` is NOT on it — the footer pointer and guessing are its discovery paths. *Rejected*: adding `cheatsheet` to the curated list (it is the reveal, not a listed utility).
- **Coverage recomputed at runtime, not pinned by a test alone** (change `cdbr`) — `CHEATSHEET_GROUPS` + `CHEATSHEET_ALIASES` are data; `buildCheatsheet` recomputes covered/missing against the live `Object.keys(COMMANDS)` on every run, so a future key degrades to an honest `uncategorized` listing in production, never a silent omission. The `uncategorized` group renders through the same dim-header + chunked-line path as the five named groups — one render path, no second format to keep correct.
- **Lib takes `commandKeys: string[]`, not the `COMMANDS` record** (change `cdbr`) — Set membership over `Object.keys(COMMANDS)` (own properties only — the o33t own-property guarantee holds by construction) keeps the pure lib decoupled from the island's record shape. *Rejected*: passing the record and using `Object.hasOwn` inside the lib (couples the lib to the record type for no behavioral gain).
- **Width budget = 74 joined chars (+2 indent = 76 total)** (change `cdbr`) — reproduces the user-approved preview's classics chunking exactly (its first line is 74 joined chars ending at `sl`); navigate (87 joined chars) wraps by the same greedy rule. One rule, no special-casing. *Rejected*: a larger budget to keep navigate on one line (would clip into horizontal scroll on laptop widths — the documented GREETING concern).
- **All-stale groups dropped entirely** (change `cdbr`) — an orphan dim header over nothing is broken output; dropping is the graceful degradation consistent with stale-entry tolerance (unreachable with the shipped data, pinned by test).
- **Card header from `root.short`, never the hand-written `SYNOPSIS`** (change `37ng`) — the json IS the captured `-h` output, so the card is vn39-clean by construction; `SYNOPSIS` remains `man`/`cd`'s voice, untouched. The bare name informs in place (a card, not a navigation) — yanking the page on a probe would repeat the misclick-feel the cuur nav beat was built to fix. *Rejected*: navigating on a bare name (that is `cd`'s job); sourcing the card from `SYNOPSIS` (hand-written, drift risk).
- **Frontmatter enumerates `help/*.json` via `readdirSync`, not a second roster const** (change `37ng`) — the island's `TOOLS` is unreachable from frontmatter; a duplicate roster is drift risk; the directory listing IS the collection (a stray extra file adds an unreferenced payload entry, harmless). *Rejected*: a `TOOL_SLUGS` frontmatter const (drift).
- **Per-tool skip-degrade in the frontmatter, deliberately unlike `VersionTable`'s build-stop** (change `37ng`) — VersionTable already build-stops on any missing/invalid rostered doc, so it remains the build's defect gate and the terminal's `safeParse`-skip can never mask a committed defect; the island additionally guards the element parse (the sessionStorage try/catch discipline: absent/malformed → empty record → SYNOPSIS+nav fallback for every card). *Rejected*: build-failing in the terminal too (duplicates the gate; couples the card to interim producer states).
- **Normalizations defined in the lib, applied at build time** (change `37ng`) — the frontmatter knows `doc.tool` (the binary name, needed for the short-prefix strip); the slim payload deliberately omits it — so the short strip is build-time-only while `buildToolCard` re-applies the (binary-independent, idempotent) usage strip defensively. The lib defines them (testable), the frontmatter applies them. *Rejected*: carrying the binary name in the payload (dead weight for one build-time-only transform).
- **Lib descriptors carry final rendered text incl. the 2-space indent; island maps `kind` → class only** (change `37ng`) — all width math (padding, truncation, budget) in one tested place so tests pin exact rendered text. *Rejected*: island-side indent (splits the width budget across two files).
- **Header clamped to the same 76-char budget** (change `37ng`) — idea's `root.short` makes the header 80 chars; the horizontal-scroll rationale (`white-space: pre`) applies to every card line, not just sub lines. *Rejected*: unclamped header (clips into horizontal scroll).
- **`shll` keeps its splash; only the nav line is appended** (change `37ng`) — the splash is the brand moment, distinct from the cards (and why `shll` stays in the cheatsheet's `classics`, not `tools`); its card data still ships in the payload (uniform 7-tool roster, dispatch verification in dist). *Rejected*: sourcing the splash from json (hand-written art is the point).
- **Six `HELP_DETAIL` entries via a `toolCardHelp(slug)` factory; `rk`/`fab` hand-written** (change `37ng`) — six near-identical entries hand-copied is drift risk (the one-body-no-drift ethos); the alias entries differ meaningfully (they teach the binary-name relationship). *Rejected*: eight hand-copied entries.
